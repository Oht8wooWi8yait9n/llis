NASA Lesson #5861: Schedule Integration Using Multiple Software Tools

Date: 2016-09-07
Organization: Marshall Space Flight Center
Program Phase: Formulation

Topic / Category: Program and Project Management, Acquisition / procurement strategy and planning, Program planning / development and management
Source: View Official NASA LLIS Entry (live system)

Driving Event / Description

The event driving this lesson learned is the pilot conducted on the CxP Extravehicular Activity (EVA) Project as part of the Agency’s Earned Value Management (EVM) Capability Project.

Lesson(s) Learned

Without a clearly defined schedule integration approach, using multiple scheduling tools within a single project can impact efficient and effective schedule management and analysis.

Recommendation(s)

While it is a best practice that all project partners use a common scheduling tool to support the total program or project Integrated Master Schedule (IMS), it may not be practical. Therefore, NASA contract proposals with schedule reporting requirements and NASA program and project agreements should contain language outlining software tool interface (IMS, EVMS cost engine, etc.) delivery requirements, standard code fields, and any restrictions on specific tool features that do not support the primary software tools to be used by the project. These requirements should be defined in the contractor Data Requirements Documents (DRDs) or appropriate program and project agreements.

Evidence / Additional Context

NASA Requests For Proposals (RFPs) contain DRDs that adequately identify tool interfaces and data exchange protocols for cost and schedule reporting to allow NASA projects to integrate contractor cost and schedule data with the project data. Additionally, program and project agreements clearly define the schedule integration approach with defined tool interfaces and data exchange protocols to allow NASA projects to create the project IMS and provide schedule data, when necessary, to NASA programs.
