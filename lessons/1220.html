NASA Lesson #1220: Verification of program requirements at the element level

Lesson ID: #1220 (Database ID: 1220)
Date: 1998-10-08
Organization: Johnson Space Center
Program Phase: None
Source: View Official NASA LLIS Entry (live system)

Driving Event / Description

Throughout 1A/R and 2A verification closure (stage level), considerable resources were expended gathering element level compliance data to provide closure of the identical requirements at the system level (ISS, USOS, AIRD).

Root cause: Initial planning did not take into account that some system level requirements are met if and only if the same requirements are met by each element on a given flight. Efficiencies can be realized by transferring the verification responsibility for such requirements to the Functional Configuration Audit (FCA) process.

Lesson(s) Learned

Proper planning and allocation of verification roles and responsibilities must occur to ensure efficient, crisp verification of program requirements

Recommendation(s)

In staged or incremental verification planning, identify system level requirements that are met if and only if the corresponding requirements are met by the element on that flight. Use the VLN (verification logic network) to reflect that the verification of such requirements is taken care of by the elements' FCA process. No further closure is required at the system level. (This process is being implemented now among EV&CS and other teams.)
