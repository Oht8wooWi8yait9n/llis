NASA Lesson #1481: Take CM Measures to Control the Renaming and Reuse of Old Command Files (2002)

Lesson ID: #1481 (Database ID: 1481)
Date: 2004-06-02
Organization: Jet Propulsion Laboratory
Program Phase: None
Mission Directorate: Aeronautics Research, Human Exploration and Operations, Science
Source: View Official NASA LLIS Entry (live system)

Driving Event / Description

During the Mars Odyssey mission, the Operations Team had been executing a “get-all-files” software script for several months when they discovered that the script had been returning an incorrect version of the light time file (LTF) (Reference (1)). The LTF contains data on spacecraft-to-Earth or Earth-to-spacecraft transmission time that is used to build Mars Odyssey sequences that command the mapping of Mars. If the LTF is not specified by the user, the 'autogen' script searches the project database (PDB) for the latest LTF that covers the time period needed by the sequence (Reference (2)).

It was determined that the script was operating properly, but that the Navigation Team had taken an old Mars Global Surveyor (MGS) LTF file and renamed it. This created a “new” LTF file with an erroneous creation time recorded in the file header that was earlier than that of the previous, outdated LTF. Hence, autogen always recognized the old, unneeded file as being the most recent.

The error required operations personnel to manually edit the environment file that specifies which files should be included in the Sequence Generator ('SeqGen') run. This editing occurred for several months following initial discovery of the erroneous LTF version. The error was eventually corrected by wrapping the LTF with a new SFDU (Standard Formatted Data Unit) header indicating an updated creation time that flags it as the latest file created. The data content of the LTF did not change.

Recommendation(s)

Establish a Interplanetary Network Directorate (IND) policy and software configuration management (CM) procedures that will preclude the renaming of old command files, parameter files, or any other command sequence resources as “new” files without adequate oversight.

Evidence / Additional Context

JPL has referenced this lesson learned as additional rationale and guidance supporting Paragraph 6.15.2.9 ("Engineering Practices: Configuration Management - Implementation"), in the Jet Propulsion Laboratory standard "Flight Project Practices, Rev. 7," JPL DocID 58032, September 30, 2008.
